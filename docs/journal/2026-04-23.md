# 2026-04-23 — M4.8 / M4.9 / M4.9.1 — polish pass closes Phase 3

## Summary

Three consecutive polish passes transformed the M4.x research-first
codebase into an installable library. All three landed in a single
working day; the commits are small enough to bisect cleanly.

- **M4.8** (commit `3c89795`): structural refactor. Unified `JEPA` +
  `build_jepa` / `load_jepa` registry subsumes the three
  milestone-specific composers (v3 LeWM, v4 DINOv3-CLS, v5
  DINOv3-patch). `MPPIPlanner` with pluggable `CostFn` strategy
  (`MSECost` / `PatchMSECost` / `ValueHeadCost`) replaces the
  if/else branching in the old `LowLevelPlanner`. `JEPATrainer` shared
  training loop (BF16 + `torch.compile` + fused AdamW + cosine LR +
  compile-key normalization on ckpt save) subsumes the four legacy
  training scripts. `vit-train` / `vit-plan` / `vit-eval` /
  `vit-collect` wired via `pyproject.toml:[project.scripts]`, each
  driven by a YAML config with dotted-path overrides. 36 CPU tests
  (35 unit + 1 integration) running in ~9s via mocked DINOv3 fakes.
  LeWM vendored into `src/vitruvian/lewm_compat/` (~550 LOC under our
  NOTICE).

- **M4.9** (commit `dbc4747`): closed the six load-bearing gaps M4.8
  left behind. `vit-train` is self-sufficient on cache MISS (inline
  DINOv3 precompute); `vit-collect` is a real orchestrator (subprocess
  workers + streaming HDF5 merge ported from the legacy scripts);
  `scripts/migrate_ckpt.py` rewrites legacy v4/v5 checkpoints on disk.
  Deleted: 9 legacy scripts, `src/vitruvian/hwm/` shim layer (15
  files), `external/le-wm` + `external/hwm` submodules. 163-line LeWM
  diff preserved at `docs/archive/lewm_local_edits.patch`.

- **M4.9.1** (this commit): GPT-5.5 cold-review cleanup pass. Nine
  findings; the load-bearing one was that `training/losses.py:
  prediction_loss` had been using LeWM upstream's unusual recipe
  (``tgt_emb = emb[:, n_preds:]``, i.e. n_preds-step extrapolation
  from each context position) rather than the standard 1-step TF
  target the docstring advertised. Investigation via
  `docs/archive/lewm_local_edits.patch` confirmed the slice was
  upstream LeWM, not a port bug — so M4.5 through M4.7 trained with
  LeWM's recipe faithfully. M4.9.1 restores the standard Terver
  recipe (`tgt_emb = emb[:, 1:ctx_len+1]`) + consistent 1-step
  rollout. A semantic-guard unit test now fails loudly if the old
  offset returns. Mechanical fixes: dropped the `lewm-v3` stub from
  the BACKBONES registry; renamed `compiled_no_grad_forward` to
  `compile_and_warm` (docstring now honest); added collection
  fail-loud + `--allow-partial`; scoped bare `pytest` to `tests/`
  (was collecting 96 vendor tests); renamed
  `configs/eval/30_run_matrix.yaml` → `17_run_matrix.yaml` to match
  its actual row count; full docs refresh.

## Phase 3 closure

With M4.9.1 landed, Phase 3 is complete. The Vitruvian codebase is
now an installable library with:

- Unified `JEPA` + registry for backbone/predictor swaps.
- `MPPIPlanner` with pluggable cost strategies.
- `JEPATrainer` shared training infrastructure.
- CLI: `vit-train` / `vit-plan` / `vit-eval` / `vit-collect`.
- 51 CPU tests (48 post-Stage-1/4/6 of M4.9.1) running in ~15s.
- Zero `sys.path.insert` in `src/`. Zero `vitruvian.hwm` imports.
- No retired-submodule dependencies.

Next up: **Phase 4 — self-learning.** Intrinsic motivation, episodic
memory, long-horizon and sparse-reward tasks. Scope open-ended; no
committed milestone list yet.
