# 2026-07-02 — Full-repo review + fix pass (M6 hardening)

A workspace-wide review (three parallel readers over models/training,
planning/CLI, data/env/infra) surfaced a batch of issues — two of them real
M6 bugs that would have silently corrupted the pending Fast-LeWM train/eval —
and this session fixed **all** of them, from the critical bugs down to the
smallest hygiene. Suite: **88 unit tests green** (was 68), `mypy --strict`
clean, `uv.lock` consistent.

## Critical (would have broken the M6 run)

- **Prefix-rollout off-by-one** (`models/jepa.py::_rollout_prefix`). `n_future =
  T - H` dropped the last action, so a v6 rollout returned `T` frames vs the AR
  contract's `T+1` and MPPI scored a terminal that the last planned action never
  touched. Fixed to `n_future = T - H + 1` / `fut = action_sequence[:, :, H-1:]`.
  Guarded by a new AR-vs-prefix rollout-contract test + a block-chaining test.
- **Test-time adapter crashed on v6** (`planning/adapt.py`). It always used the
  AR-only `prediction_loss` → the prefix predictor's 3-D-anchor assertion. Now
  routes to `prefix_prediction_loss` via `is_prefix_predictor` and forces
  `history_size=1` (Fast-LeWM anchors on one frame). New prefix-adapter test.
- **MPPI noise was unseeded** (`planning/mppi.py`). Draws came from the ambient
  global RNG, so eval rows weren't reproducible and the frozen-vs-`--adapt` A/B
  was confounded by different noise streams. Added a per-planner
  `torch.Generator` (`seed=…`); `vit-eval`/`vit-plan` pass their seed. **The
  AdaMPPI deltas from 2026-07-01 should be re-run seeded before they're
  trusted;** Q1a/Q1c and the coarse Q1b/steering conclusions stand.
- **Proprio train/plan conditioning mismatch** (`training/losses.py`). Dropout
  zeroed the encoder *input*, so dropped frames still added the learned constant
  `proprio_encoder(0) != 0`, while plan-time rollouts add nothing. Now masks the
  encoder *output* so *dropped ≡ absent ≡ plan-time*. v6 config comment
  reconciled with the code (proprio is train-time-only, plan is proprio-free,
  `proprio_dropout` 0.25→0.5). New "dropped == absent" equivalence test.
- **Collection frame-0 command bug** (`data/collection.py`). The joystick
  command was pinned *after* `reset` had already baked a random command into the
  obs, so every episode's frame 0 (proprio + policy action) tracked a random
  command. Now a pinned settling step runs before recording; every frame is
  command-consistent. (Fix lands before any Q2 recollect.)
- **`mypy --strict` was broken by the M6 commits** (3 errors) and **CI only ran
  on `main`**, so the branch was never checked. Fixed the types; CI now triggers
  on every branch push.
